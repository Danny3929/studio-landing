## Accessibility problems found
- 2026-10-27: Work filter built as toggle buttons with `aria-pressed` (not ARIA tabs, because there is one grid that changes, not separate panels). Status line is a live region ("Showing 2 of 3 projects"). Tiles that do not match are removed from the page so Tab cannot reach them. Focus stays on the pressed button. Measured contrast: buttons 8.81:1, tile text 11.31:1, status 13.57:1. Drawings are centred (within 0.2 units) and hidden from screen readers; the caption carries the meaning.
- 2026-10-27: Services: heading order h1 > h2 > h3, services are a real list (4 items), icons hidden from screen readers (the text carries the meaning). Contrast measured from the rendered page: terracotta brick 4.59:1 (text and lines), sand 11.31:1, green 8.81:1, charcoal 13.57:1; icon accents all at least 3.83:1 (graphics need 3:1). An empty `benefit` no longer leaves an empty paragraph.
- 2026-10-27: Nav built with Joy's three menu rules (opens with a button, closes with Escape, traps focus) plus: focus returns to the Menu button on close, a click outside closes it, growing to laptop width closes it, closed links are hidden so Tab skips them, `aria-expanded`/`aria-controls` on the button, 44px touch targets, and a "Skip to content" link as the first Tab stop. Checked with 21 keyboard and layout checks in a real browser.
- 2026-10-27: If the headline text is ever empty, the Hero renders an empty `<h1>`, so screen readers get a heading with no words. Nothing in the code guards against it yet. Content now lives in `src/data/hero.js`; a test or check for empty text should be added later.
- 2026-10-24: My README rule banned terracotta icons on sand, but graphics only need 3:1 (3.83:1 passes). Text needs 4.5:1. Rule corrected to apply to text only.

- 2026-10-27: Pricing: billing choice is two toggle buttons with `aria-pressed` and a live status line ("Showing annual care plan prices"). The highlighted tier has a text badge ("Most chosen"), not colour alone. Visual order equals Tab order on every width. Measured contrast: all text pairs at least 4.59:1 (lowest is cream on terracotta, the Choose Starter button), toggle and cards 8.81:1 to 13.57:1. Toggle buttons are 44px high.

- 2026-10-28: Contact form: every field has a visible `<label>` tied by `for`/`id`, and required fields say "(required)" in words. Errors are tied to fields with `aria-describedby`, fields get `aria-invalid`, errors show a "!" sign and words (not colour alone), and an alert summary says "Please fix 3 fields below". Focus moves to the first bad field on a failed send, and to the thank-you message after a send. Errors appear only after a field is left or Send is pressed. Browser pop-up bubbles are off (`noValidate`) so our wording is shown. Field text pairs at least 4.59:1; field borders at least 3:1.

- 2026-10-28: FAQ accordion: each question is a real `<button>` inside an `<h3>`, with `aria-expanded` and `aria-controls`; each answer is a region labelled by its question. Closed answers use the `hidden` attribute, so they are out of the Tab and reading order. Several can be open at once (nothing closes unexpectedly). Rows are at least 44px high, the +/- sign is drawn in CSS and hidden from screen readers (the words and `aria-expanded` carry the meaning). Contrast: text 8.81:1 to 13.57:1, sign 7.35:1 (graphics need 3:1).

- 2026-10-28: Footer and trust strip: one `<footer>` landmark outside `<main>`; its link list is `aria-label="Footer"` so it is not confused with the "Main" nav. The trust strip has a screen-reader-only `<h2>` (1px, not `display: none`) so it can be found by headings. The default green focus ring is 1.54:1 on the charcoal footer (nearly invisible), so the footer uses a cream 3px ring (13.57:1). Footer links are at least 44px high. Text pairs 11.31:1 to 13.57:1; the terracotta brick graphic is 3.83:1 (graphics need 3:1). The trust strip makes only promises the FAQ also makes; no invented client counts, logos or ratings.

- 2026-10-28: Theme toggle: a real `<button>` with `aria-pressed` (true = dark), a fixed accessible name "Dark theme" (a name that changes with the state would be read twice), a 44px target, and an icon hidden from screen readers. Tab order equals visual order: logo, theme button, Menu button, links (phone), and logo, theme button, links (laptop). The open mobile menu's focus trap includes the theme button. Dark contrast measured by a script over every visible text in all states (open FAQ, errors, annual pricing): all text at least 4.5:1 (large text 3:1), UI boundaries and focus ring at least 3:1 (focus ring 9.05:1). `color-scheme` is set so scrollbars and form controls follow the theme.

- 2026-10-28: Testimonials carousel follows the W3C carousel pattern: a labelled region ("Client testimonials", `aria-roledescription="carousel"`), each slide a group labelled "n of 3", only the current slide visible (the others have `hidden`, so they are out of Tab and reading order), real `<blockquote>` and `<figcaption>`. It rotates every 7 seconds ONLY if nothing pauses it: Pause button, mouse pointer over it, keyboard focus anywhere inside it (Joy's requirement), hidden browser tab. Under reduced motion it never rotates and the Pause button is not shown. The live region is `off` while it rotates by itself and `polite` when paused or after a button press. Slides swap instantly (no animation). Contrast measured in both themes on all 3 quotes: text at least 4.5:1, button border 8.81:1 / 9.05:1, side bar 3.83:1 / 4.57:1.
